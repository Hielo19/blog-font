# Hielo 本地博客预览

保留原博客插画、头像和柔和青绿色氛围的个人博客，包含首页和《一些近况分享》阅读页。使用 Sites 生成的 React / TypeScript / Vinext 项目，导出为静态网站。无后台，无数据库，无运行时 WordPress 请求。

## 本地使用

需要 Node.js 22.13 或以上。

```sh
npm install
npm run dev
```

打开终端显示的本地地址（默认 http://localhost:3000）。

- 首页（唯一的玻璃主题）：`/#/`
- 文章：`/#/post/recent-updates`
- 归档、关于、RSS 和《Welcome to My Blog》打开原博客。

玻璃主题固定使用「浅色薄荷青／深色雾蓝灰」，右上角仅保留太阳／月亮按钮切换明暗，外观菜单已按设计移除。没有已保存的明暗偏好时默认跟随系统，手动切换后记住所选模式。旧版配色和动效设置会被忽略；存储不可用时仍可正常切换。动效遵循系统的减少动态效果设置。

独立插画主题、风格切换入口及其专用样式已移除。原 `/glass` 路径已撤下，请使用根路径；玻璃首页仍包含已确认的插画首屏及个人信息收拢动画。浏览器偏好的存储键沿用原值，保留已保存的外观设置。

首页先完整展示原博客插画、头像与站名；向下滚动或点击「向下浏览」时，中央身份信息沿滚动方向收拢到左侧个人卡片，文章模块同时进入视口。首屏导航保持悬浮，进入内容区后贴到窗口顶边，并切换当前栏目提示。

毛玻璃参考用户提供的烟灰磨砂导航，采用低染色的半透明底层、局部模糊、单层细边与柔和投影，减弱深色背景遮罩并移除浮雕高光。支持的浏览器使用连续曲率圆角，其他浏览器回退为普通圆角。文章正文保持接近不透明的阅读底色，不受图片干扰。

主卡片使用约 20px 的连续曲率圆角；直接位于插画上的章节标题使用无边框渐隐底层，小链接、原博客入口和页脚使用 9px 小圆角的轻薄磨砂标签，避免增加新的大卡片。

卡片进入视口时依次淡入，个人卡片会从首屏身份信息的位置向左下方归位；图片与链接有轻微悬停反馈，首页与文章间使用浏览器原生页面过渡。滚动使用 SmooScroll 1.2.0 manual-lite 的 React 适配：保留原生滚动条与输入，内容容器以 0.8 秒、`cubic-bezier(.35, .73, .5, 1)` 缓动追随滚动位置，滚轮、键盘和拖动滚动条均采用这一效果。点击「向下浏览」使用独立的约 0.7–1.25 秒渐入渐出过渡，让原生滚动位置与画面同步推进；末尾按导航实际高度落位并聚焦内容区，滚轮、触控及键盘可随时中断。Lenis 不再初始化或加载样式。返回文章列表立即恢复原来的可见位置与所点击链接的键盘焦点。启用系统减少动态效果后停用这些动画与平滑滚动，恢复普通文档流。

阅读栏根据顶部导航的实际高度吸顶，导航换行或文字放大时会同步调整，避免返回按钮与阅读进度被遮挡。

「向下浏览」以首屏渐变蒙板的实际下沿对齐导航栏的实际下沿，落点与身份动画共用 `features/blog/home-boundary.ts`。蒙板由独立的 `heroScrim` 元素绘制；首页内容在其后保留桌面 42px、手机 28px 留白。动画结束时复核导航收缩后的边界，减少动态效果下也会在布局更新后立即校准；不再把通用锚点避让距离叠加到这个落点。

固定导航、插画背景与首屏身份信息置于平滑容器外；阅读栏在容器内按画面实际位置补偿吸顶，并在文章末尾停止。阅读进度与首屏收拢动画也使用画面位置，避免提前于缓动内容更新。适配层由 React 管理挂载和清理，不执行上游脚本中的 DOM 自动搬移逻辑。来源、版本与修改说明见 `third-party/smooscroll/README.md`。

## 修改内容和设计

最近记录采用双列错落卡片，在 1050px 及以下变为单列。每张卡片展示一篇文章；六张带「示例」标签的预览内容集中在 `data/blog/journal.ts`，不会成为真实文章或生成阅读链接。时光归档与 RSS 位于侧栏「说说」下方。此次试验的原版备份与恢复步骤见 [卡片改版回退说明](docs/journal-cards-rollback.md)。

- `app/`：薄路由入口、根布局与全局主题样式。
- `features/blog/`：首页和阅读页组件、页面组装、身份动画及玻璃样式。
- `features/theme/`：系统偏好与本地明暗记忆。
- `features/scroll/`：平滑滚动引擎与 React 适配。
- `models/blog.ts`：前端内容类型。
- `data/blog/posts.ts`：真实文章、日期、摘要、配图和来源。
- `services/blog/`：统一内容读取入口，当前使用本地实现。
- `services/api/`、`contracts/`：为 Gin 请求层与接口协议预留的目录。
- `config/site.ts`：站点地址；`lib/`：通用工具。
- `public/assets/`：原博客背景、头像和文章图片。

详细目录和职责见 [项目结构](docs/architecture.md)，接入步骤与静态导出限制见 [Gin 后端接入](docs/backend-integration.md)。当前不请求后端，目录整理不改变页面和公开路由。

文章正文保留原文；首页摘要经过精简。正文署名 Hielo，保留原文的 CC BY-NC-SA 4.0 许可链接。图片均来自 hielo.cn，未加入游戏官方宣传素材。

## 构建

```sh
npm run build
```

项目启用静态导出，输出位于 `dist/client`。构建后运行 `npm start`，或由任意普通静态文件服务器预览该目录。开发预览不修改或发布到 hielo.cn。

构建入口使用 Vite 构建 API 与锁定版本 Vinext 的静态导出 API，让 Node 正常释放资源，避免当前 Windows / Node 24 下 Vinext CLI 强制退出触发的原生句柄异常。构建或导出失败仍会以非零状态退出。

## 验收要点

检查 390px、768px、1440px 宽度；文章打开、刷新、前进后退和返回位置；键盘导航、文字放大及减少动态效果。返回位置仅保存于当前浏览器标签页的 sessionStorage，存储不可用时使用内存。

代码检查：运行 `npm run test`、`npm run lint`、`node node_modules/typescript/bin/tsc --noEmit --incremental false` 和 `npm run build`。滚动测试使用可控的 DOM 模拟验证位置恢复、吸顶边界及清理；当前项目没有自动化浏览器测试。
